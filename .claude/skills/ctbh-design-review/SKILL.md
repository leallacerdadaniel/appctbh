# CTBH Design Review

## Contexto

Design rules only work if they are checked. This skill is the quality gate for `ctbh-design-system`: a code check that catches rule violations, then a visual check of real screenshots, repeated until the screens pass. The owner judges the app by how it looks on a phone, so the review always happens at phone width, in light mode.

## Etapa 1: Static check

From the app folder (`App CTBH/app`):

```bash
bash .claude/skills/ctbh-design-review/scripts/check-design.sh
```

Fix every violation it lists before looking at screenshots. If a violation is intentional, change the rule in `ctbh-design-system` first and record why in its Atualizações Progressivas.

## Etapa 2: Typecheck and lint

```bash
npx tsc --noEmit && npx eslint src
```

## Etapa 3: Open the app at phone size

1. Make sure the dev server runs: `lsof -i :8081` or start it in the background with `npx expo start --web`.
2. With the Playwright MCP tools: resize to **390 × 844**, navigate to `http://localhost:8081`.
3. Demo login: any e‑mail + `ctbh2027`, then set a new password (8+ chars with a digit, e.g. `bonjour2027`). The session persists in the browser after that.

## Etapa 4: Screenshot every changed screen

Save screenshots under `.playwright-mcp/` (Playwright only writes inside the home folder) with descriptive names, e.g. `review-home.png`. Screens scroll inside a ScrollView, so a full-page screenshot only shows the viewport: scroll the inner scroller with `browser_evaluate` and take one screenshot per viewport. Look at each image with Read.

Routes: `/` (home), `/maison`, `/chez-toi`, `/calendar`, `/bh` (`?section=guide|explorer`), `/profile`, `/requests`, `/apartment/payments`, `/nearby`, `/restaurants`, `/restaurants/<id>`, `/login`, `/change-password`.

## Etapa 5: Compare against the checklist

Go through [references/checklist.md](references/checklist.md) for each screenshot. Write down each failure as `screen — rule — what to change`.

## Etapa 6: Fix and repeat

Fix the failures, then repeat Etapas 1–5 for the affected screens. Stop when a full pass has no failures. Also check the browser console (`browser_console_messages`, level error) is clean.

## Etapa 7: Report

Tell the owner, in Portuguese, which screens were reviewed, what was fixed, and anything that still needs their decision. Offer the screenshots.

## Regras

- Never declare a visual change done without looking at a screenshot of it.
- Review in light mode at 390 px width; also glance at 768 px if layout code changed.
- Check both languages when strings changed (switch in Profile).
- Do not "fix" a failure by weakening a rule; ask the owner if the rule seems wrong.

## Common Issues

### Screenshot is blank or shows the login screen
Cause: fonts still loading or the session was lost. Solution: wait ~2 s with `browser_evaluate` (`new Promise(r => setTimeout(r, 2000))`), log in again.

### "File access denied" when saving a screenshot
Cause: Playwright only writes inside the home folder. Solution: use a relative name like `.playwright-mcp/review-home.png`.

### Typed routes error after adding a screen (`"/x" is not assignable`)
Cause: `.expo/types` is regenerated by the dev server. Solution: make sure the server is running, wait a few seconds, rerun `tsc`.

## Atualizações Progressivas

Add new checklist items to `references/checklist.md` whenever the owner points out a visual problem that the checklist did not catch, with the date.
